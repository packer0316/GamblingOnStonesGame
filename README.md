# 一刀窮 · 一刀富 — 賭石

緬甸翡翠原石的賭石遊戲原型。攤上擺五塊原石，挑一塊買下，打燈、擦皮、開窗、切刀，每一次見肉市場都會重新出價——見好就收，還是再賭一刀。

技術：three.js（WebGL2）+ Vite。模型、材質、特效全部由程式產生，沒有任何外部美術檔；每一塊原石都是從一個種子長出來的**實心體積**，不是貼圖。

## 執行

Windows 直接雙擊 `start.bat`：第一次會自動安裝套件，接著啟動伺服器並開啟瀏覽器；關掉那個視窗就停止。

或手動：

```bash
npm install
npm run dev        # http://127.0.0.1:5183
npm run build      # 輸出到 dist/，可直接放到任何靜態主機
```

需要支援 WebGL2 的瀏覽器（3D 貼圖）。

## 玩法

| 操作 | 說明 |
| --- | --- |
| 點攤上的石頭／價牌 | 上手細看：拖曳旋轉、滾輪縮放。這時還沒花錢 |
| 打燈（T，免費） | 室內燈暗下來，把手電壓在滑鼠指的位置。買之前就能打 |
| 買下 | 付開價，石頭上工作檯 |
| 擦皮（1）／開窗（2）／開大窗（3） | 點石頭上有皮的位置，牙機把皮殼磨掉。越大的窗看得越多，工錢也越貴 |
| 切一刀（4） | 左鍵在石頭上拖一條線，紅色雷射線就是下刀位置；確認後水鋸下刀。切開的每一塊都可以再切 |
| 翻面（F，免費） | 把正在看的那一塊翻過來 |
| 賣出 | 以市場現在的收購價脫手，之後揭曉買家把它全解開的真相 |
| 右鍵拖曳 | 任何時候都能轉視角（畫切線時左鍵是畫線） |
| Esc | 取消工具／取消下刀／放回攤上 |

本金不存檔，每次開啟或重新整理都是 ¥500,000（[src/game/tuning.js](src/game/tuning.js) 的 `startCash`）。攤上的東西全都買不起時會出現「補充本金」，補回 ¥500,000。

**目前關閉**：[src/game/tuning.js](src/game/tuning.js) 的 `gm: false`。關閉時右上角沒有 GM 按鈕、`` ` `` 鍵沒有作用、網址的 `&cash=` 也被忽略，本金只能靠玩來增減。改成 `true` 就恢復以下功能。

右上角的 **GM** 按鈕，或鍵盤左上角的 `` ` `` 鍵，隨時可開（演出進行中也可以）。

- **輸入金額按「設定」或 Enter**：`5000000`、`5,000,000`、`500萬`、`1.5億` 都認得。
- **前面加 `+` 或 `−` 是加減**：`+50萬`、`-5000萬`。
- **快捷鈕**：±1 萬、10 萬、100 萬、1000 萬、1 億、10 億；歸零；回到起始本金。
- 本金不會低於 0，上限 ¥99,999,999,999。

改完之後攤位價牌（買不起的會劃掉）、「買下」按鈕、「補充本金」都會立刻跟著更新。GM 只動本金，不動石頭的價錢與內容；重新整理頁面後本金回到 ¥500,000。邏輯在 [src/game/game.js](src/game/game.js) 的 `setCash`／`addCash`／`parseMoney`，介面在 [src/ui/hud.js](src/ui/hud.js)。

## 賭石的學問，在遊戲裡各是什麼

遊戲裡沒有「提示」。該看的東西都畫在石頭上，跟真的一樣要自己判斷。

- **場口**：九個場口（莫西沙、木那、會卡、大馬坎、莫灣基、帕敢、南奇、後江、八三），各有皮殼、個頭、種水、出色方式、裂與棉的傾向，定義在 [src/game/lore.js](src/game/lore.js)。場口只改變機率，不保證任何事。
- **皮殼**：白鹽沙、黃沙、紅沙、黑烏沙、蠟殼、水翻砂。砂粒粗細跟底下的種水相關（砂細種老），但會騙人。
- **松花・蟒帶・癬**：皮上的綠斑、帶狀紋、黑斑，是著色器直接取樣「皮下那一層的真實成分」畫出來的——所以苗頭是真的，但色只貼著皮（靠皮綠）的石頭，松花一樣漂亮。
- **霧**：皮與肉之間的一層（白、黃、紅、黑霧），開窗時在窗口邊緣看得到一圈。
- **種水**：磚頭料 → 豆種 → 糯種 → 糯冰 → 冰種 → 高冰 → 玻璃種。決定光在肉裡走多遠：豆種像粉筆，冰種看得進去一兩公分。
- **色**：色帶、色團、飄花、滿色、靠皮綠五種長法，另有紫羅蘭（十春九豆）、黃翡紅翡（只在皮下）、黑癬（會吃綠）。
- **裂・石紋・碎裂・棉**：裂是有起伏的圓片，皮上看得到的只是冒出來的那幾條。裂決定能不能出手鐲。棉只有在夠透的肉裡才看得見。
- **打燈**：光從壓燈的位置進去，穿過同一份體積，再從皮殼透出來。種越老光暈走越遠（豆種只亮燈頭周圍一圈，冰種整顆發亮）；光暈的顏色就是皮下那層肉切開會看到的顏色——白底是白光，一絲飄綠就是一絲淡綠，滿綠才整片綠，皮下有黃翡偏琥珀色——燈不會把顏色照得比切面濃；黑癬是光暈裡的黑洞；裂會擋光，裂的另一側明顯較暗，連皮上看不到的裂也一樣；皮越厚、蠟越重透出來的光越少，從窗口打則直接進肉。燈只看得到皮下那一層，所以靠皮綠一樣會透綠。
- **機緣**：每個場口都有小機率長出五種好東西（各場口的機率在 [src/game/lore.js](src/game/lore.js) 的 `lucky`，總開關是 [src/game/tuning.js](src/game/tuning.js) 的 `luck`）：
  - **帝王綠**：濃、陽、正、勻的滿色，種水冰種起跳。
  - **冰紫羅蘭**：冰種以上、整塊泛紫的紫羅蘭——「十春九豆」的那一塊例外。
  - **春帶彩**：紫底上一條粗的綠帶，皮下再帶翡色就是福祿壽。
  - **皮粗肉細**：皮下是普通的肉，石心高一兩個種水等級。
  - **藏色**：石頭中間一團濃色，完全不到皮。

  前三種有一半左右是「明料」，皮上、燈下都看得出來，市場照價開，通常很貴；另一半和後兩種是「藏」的——好東西從皮下半公分到兩公分才開始，皮上乾乾淨淨。帝王綠藏的時候多半是石心一團色根，十塊裡有一塊是整個石心滿色。藏料的線索只有幾個：皮下的肉本身夠透（打燈光暈走得遠）；光穿過石心會染色（燈頭附近是白的，遠處的邊緣透綠或透紫）；皮粗肉細的石頭，砂會比皮下那層肉該有的更細。
- **賭性**：市場看不到石心，但知道每個場口多常藏貨、藏貨的石頭皮下種水大概在哪個範圍。所以種嫩的場口裡一塊皮下冰透的素石，開價會比它「看起來」貴一截（品相上會標「賭性大」，老闆也會講）；同樣的石頭在種老的場口就沒什麼溢價。從石心切過一刀，賭性就兌現或歸零；開窗碰不到石心，溢價還在。
- **擦漲・切漲・切垮**：見下方「市場怎麼出價」。

## 石頭是怎麼做的

每塊石頭由 [src/stone/gen.js](src/stone/gen.js) 的 `makeStone(seed)` 擲出一組隱藏參數，`makeField(def)` 把它們變成「空間中任一點是什麼」的函式。之後所有東西都只問這一份真相：

- **體積**：[src/stone/bake.js](src/stone/bake.js) 把內部烘成兩張 112³ 的 3D 貼圖（綠、種水、棉、到皮的距離／紫、黃、黑、碎裂區）給著色器，同時降成 28³ 的小格（大石頭約 1 公分一格）給估價用。**畫出來的和算錢的是同一份資料。**
- **網格**：[src/stone/mesher.js](src/stone/mesher.js) 用 surface nets 從距離場取面。開窗是把皮往內磨一個橢圓淺盤，切刀是與半空間取交集；鋸面的頂點會貼齊到稜線上並另外複製一份，所以切面是真的平面、邊是利的。運算在 Web Worker 裡（[src/stone/worker.js](src/stone/worker.js)），鋸片還在轉的時候兩半就算好了。
- **著色器**：[src/stone/material.js](src/stone/material.js)，一個材質畫全部——皮、皮殼斷面、霧、玉肉，靠每個頂點帶的「在原皮下多深」區分。
  - 玉肉不是貼圖：每個像素沿折射方向往體積裡走 13 步，累積散射與吸收。不透的料第一步就回來，透的料一路穿過棉、色根和裂面（裂是解析式求交，所以是銳利的銀色薄片）。
  - 皮殼的起伏以公分為單位分層疊出來（一粒砂在小石頭和大石頭上一樣大）：成片剝落留下的緩台階（約 1.6 公分）、崩口與蝕坑（約 0.5 公分）、兩層細齒（1.6 與 0.75 毫米），最上面是一粒一粒的砂——每粒是一個帶著自己傾角的小晶面，大小不一，少數偏深、少數淺而亮會反光，粒徑跟著「砂粗／砂細」走。每一層的法線用的是**預先存好的斜率**（`createGradNoise` 把梯度雜訊連同它的梯度烤進一張 64³ 貼圖），不是拿相鄰像素或相鄰貼圖格相減，所以放大不會出現方格、織紋或馬賽克；小於幾個像素的層會淡出而不是閃爍。低處（坑裡、砂粒之間）積灰偏暗。水翻砂、蠟殼這類磨光的皮起伏減半；濕的皮殼水膜跟著砂粒起伏。松花、癬、透出來的翡色取樣自皮下體積；裂紋和蟒帶是解析式畫的，再近都不糊。
  - 打燈的光：每個像素從燈頭到自己腳下取 6 個樣本（路徑往石頭深處彎，因為散射光不走皮下的直線；步距大時讀體積貼圖的 mip），累積沿途的消光與染色，再解析式判斷光線有沒有穿過每一片裂。光暈從燈頭鋼圈的邊緣起算，不會被燈頭自己蓋住；皮殼的砂粒、蠟、癬疊在光暈上，亮的地方還是看得出是皮。光暈的顏色和切面共用同一個函式（`fleshMix`）讀肉質，淡色霧一樣被截掉，再淡化到切面上水光沖淡後的程度；沿途染色刻意壓得很輕。所以打燈看到的色不會比切開的濃。
  - 窗口是拋光的（清漆層 + 平滑底層）；鋸面是粗的，沖水後才有一層水膜。剛切開時整面蓋著石漿，要等沖水才看得到顏色。
  - 切面近看的東西疊在光線步進之上：
    - **晶粒**：3D Voronoi 的交織結構，格點經過扭曲、大小兩層混雜，接縫是柔和的色調變化而不是線；粗的料（豆種）看得見，越細越淡。個別晶粒的解理面會隨視角閃一下（翠性）。
    - **內含物的邊**：體積貼圖只存得下模糊的分佈，所以黑癬、色帶、翡色在著色器裡補回銳利參差的邊和周圍的碎點；鏽裂的鐵染沿晶粒往外滲。
    - **皮殼與霧**：皮殼斷面是厚薄不一的暗色硬殼；霧層貼皮處鏽、往內變淡，厚度不均，以舌狀滲進玉肉，兩道邊界都不是整齊的圈。
    - **鋸痕與水**：鋸片留下的弧形細紋；水膜的光澤不均勻（積水、變薄），反射面有緩和的起伏。水膜起伏用正弦波而不是雜訊貼圖——格點雜訊的梯度在每個格點都會歸零，在鏡面反光裡會顯出一片方格。
- **場景**：[src/scene/stage.js](src/scene/stage.js) 管渲染器、燈光、鏡頭與後製（泛光，以及大漲時的衝擊：放射模糊、色散、漣漪）。打燈時室內燈調暗到約兩成（`DIM`），檯面和石頭的輪廓還看得見，不是全黑。
- **廳堂**：[src/scene/room.js](src/scene/room.js)，秋夜裡的玉商廳堂，全部程式生成。基調是「暖燈在內、冷月在外，滿眼將落未落的楓紅」。
  - 對得到焦的是真的幾何：祖母綠絨面（暗織七寶紋、邊上兩道金線，只在燈下那一池亮）、嵌銅線的紫檀漆框、一路落到地面的櫃身。長案大小在 `TABLE`。
  - **飄落的楓葉**是真的立體葉片（72 片，七裂掌狀、沿主脈微摺、葉尖微捲，金黃到深紅五種色）：會翻轉、隨月洞門吹進來的風擺盪，落在地上或長案邊框上躺一陣再淡出。長案中央放石頭的區域不會有葉子落下，貼近鏡頭的葉子也會自動縮掉，不擋視線。
  - 對不到焦的由一個著色器畫在外圍的球面上：每條視線都算到「方盒房間」的牆上再上色，所以鏡頭一動，牆、案上擺件、門外的樹與遠山各有各的視差。邊緣故意畫得軟——鏡頭的焦在案上。
    - **四壁**：朱漆圓柱、柱頭柱腳描金，梁上一道金線；柱間是燈火透亮的花格紙窗，紙面上半映著窗外的月光，楓枝的影子在上面隨風輕搖（月洞門兩側的窗一定有，其餘隨機）。
    - **月洞門外**是暮色中的庭園，分好幾層各有視差：天邊殘霞轉紫的夜空、一輪被薄雲橫過的金色滿月；水墨層疊的遠山與山脊上亮著一盞燈的寶塔；映著天光與月光帶的湖面，水上起霧；半月拱橋與倒影合成一個圓；左右兩株紅楓（樹冠是一團團柔和融合的葉團，朝月的一側鑲亮邊），樹下石燈籠從下方把楓葉照紅，岸邊鋪滿落葉；最前景一枝楓枝從右上垂下、葉片半掩月亮，背著月光的葉子透紅；飄落的葉子邊落邊翻。構圖是照攤位視角排的（那裡只看得到門的上半部：月亮和楓樹在上），湖和橋留給走近看的時候。
    - **擺設與地面**：門兩側條案上的瓶中插紅楓（葉子被身後亮紙窗透成紅色）、原石與檯燈；梁下掛紅絹燈籠（金頂金底、紅穗）；磨光黑石地上散著從月洞門吹進來的楓葉，門前一片冷白月光。
  - 這個球面排在所有實體之後才畫，被長案擋住的像素不會算；地板倒影走省略細節的路徑（不算窗上枝影、門外細節）；離樹冠、枝條太遠的像素直接跳過。整個廳堂背景在攤位、看貨視角約 1 毫秒，月洞門佔滿全畫面時約 3.6 毫秒（內顯，GPU 沒被別的程式佔用時量的）。燈下的浮塵是一組點，燈柱是一個只從外面看得到的錐面。
  - 不要為了顆粒或暈影再加一道全螢幕後製：合成器的緩衝是 4× 多重取樣的半浮點，在內顯上每多一道要 3 毫秒以上。顆粒直接加在廳堂著色器的輸出上（順便消掉暗部漸層的色階），暈影是 CSS。

## 市場怎麼出價

在 [src/stone/appraise.js](src/stone/appraise.js)。

**真值**：每一小格肉依種水、色、瑕疵定價（對數線性，從豆種無色手鐲幾百元到玻璃種滿綠上千萬），再依離最近的裂多遠打折——離裂 4 公分以上的料能出手鐲，2 公分左右只能出牌子，貼著裂的只剩珠子小件。個頭太小的石頭不論多乾淨都出不了手鐲。全部加總就是這塊石頭真正值的錢。

**市場看到的**：市場看不到真值。它從皮下最外一層肉往內推（「皮上看到的會一路走進去」），再打上行內的保留：翡色只在皮下、松花的色不一定吃得進去、太漂亮的皮殼往場口的平均拉回。然後——

- 每開一個窗、切一刀，露出來的肉附近就由猜測換成事實（越透的料看得越深，但也只有一公分上下——所以開在靠皮綠上的窗會擦漲，要等下刀才知道色沒進去）。
- 露出來的比原先猜的好，沒看到的部分會跟著被看好（**擦漲**）；比猜的差就整塊被看壞（**切垮**）。這個外推在只看到一點點時最強，所以「擦漲不算漲」。
- 露出來的肉上有裂經過，這條裂就被市場知道了，它周圍的手鐲位全部降級。
- 還沒看到的部分有折價（沒人知道的裂、轉手價差），石頭越明朗折價越少。
- 還沒看到的部分另外帶著**賭性溢價**：這塊石頭是各種藏料的機率（場口的機率 × 皮下種水符不符合 × 皮上是不是素的，用貝氏算）乘上那種藏料平均多值幾倍（`tuning.js` 的 `hope`）。石心被看到的比例一上去溢價就消失（`hopeFade`）——所以一塊普通石頭的第一刀平均是跌的，跌掉的就是這張彩票的錢。
- 皮上整片都是濃綠的石頭（只有滿色會長成這樣）市場信它九成（`trustFull`），不像對零星松花那樣只信六成。

切得越開，市場估價就越接近真值（畫面上的「明朗度」）。賣出後畫面上會顯示買家全解的結果：實際品名、能取幾支手鐲幾塊牌子、你賣早了還是賣得漂亮。

攤位開價就是市場對這塊石頭的第一眼估價；同一塊石頭全市場誤判的方向一致，所以沒有「低買原封轉手」這回事。

## 返還

所有決定賠率的數字集中在 [src/game/tuning.js](src/game/tuning.js)。`npm run sim -- --plays` 不畫圖直接長石頭，用固定位置的窗與刀（不看石頭、不靠眼力）試幾種打法。800 塊的結果：

| 打法 | 起始本金買得起的（699 塊） | 全部（800 塊） |
| --- | --- | --- |
| 買了原封轉手 | 返還 94.9%，贏 0% | 95.0% |
| 開一個窗就賣 | 107.6%，贏 40% | 123.7% |
| 切一刀就賣 | 98.1%，贏 32% | 112.7% |
| 開窗 + 三刀全解 | 100.1%，贏 31% | 117.3% |
| 一有賺就賣 | 97.6%，贏 47% | 119.2% |

這張表是在兩項調整之後量的：**工錢**降到石價的 0.15%／0.3%／0.5%／0.6%（擦皮／開窗／開大窗／切一刀，上限 ¥200／600／1,000／2,000；原本是 0.5%／1%／1.6%／2%，上限 ¥800／3,000／5,000／10,000），**原封轉手**的收購價從估價的 86% 提到 95%（`resale`）。同一批石頭在調整前是 85.9%／99.5%／93.3%／93.9%／89.1%。

莊家優勢原本就來自這兩項，所以拿掉之後盲切的返還全部升到 100% 上下，「開一個窗就賣」超過 100%。要把優勢補回來又不動這兩項，可以調的是 `surprisePower`（一個窗把沒看到的部分重新估價的力道）和 `calib`（開價相對真值的整體水位）：`surprisePower` 0.4 加上 `calib` 全部乘 1.05，同一批石頭量出來是 95.1%／101.4%／90.2%／93.9%／88.6%。

讀這張表要注意三件事：

- 翡翠的價值分佈尾巴極長。這 800 塊裡最貴的一塊（八三玻璃種帝王綠，真值 ¥1,947 萬）就佔了全部價值的一成多，所以「全部」那一欄每次重跑會差十個百分點以上；「買得起的」那一欄比較穩。
- 這是閉著眼睛切的結果。打燈挑石頭、順著裂下刀是這個遊戲真正的賠率來源，模擬沒有算進去——尤其是藏料：燈光穿過石心會染色，市場的開價卻只算機率，看得出來的人比市場看得深。
- 模擬用 64³ 的體積（遊戲是 112³），小格較粗，數字是近似值。市場的第一眼是往皮下看兩格，格子粗看得就深，所以藏料在遊戲裡比這張表再多賺一些：用 `--vol 112` 跑 1,600 塊，買得起的石頭切一刀就賣是 98%、全解也是 98%（這兩個數字是工錢與轉手價調整之前量的，現在會再高幾個百分點）。

叫得出名字的石頭佔全部的比例：帝王綠 4.1%、冰種以上的紫羅蘭 5.1%、冰種以上的春帶彩與福祿壽 2.0%、其他玻璃種約 3%。

要更刺激或更溫和，調 `tuning.js` 的 `luck`。賭性溢價會跟著機率自動變，所以總返還只小幅移動，主要動的是一般石頭讓出多少（切一刀就賣、買得起的、64³、1,500 塊；這張表是工錢與轉手價調整之前量的，現在三列的返還都會高約五個百分點）：

| `luck` | 機緣佔比 | 總返還 | 一般石頭的返還 | 贏 | 3 倍以上 |
| --- | --- | --- | --- | --- | --- |
| 0（關掉，等於原本的遊戲） | 0% | 94% | 94% | 27% | 0.1% |
| 1（現在） | 17% | 96% | 79% | 29% | 1.6% |
| 2 | 34% | 100% | 69% | 30% | 2.5% |

`luck` 調到 2 時總返還會漂到 100% 上下，要把 `hope` 調高壓回來（調多少得重量）。只想改某一種的機率，改 `lore.js` 各場口的 `lucky`；改了藏料的大小或種水範圍（`gen.js` 的 `FINDS` 和 `makeStone`）之後，要用 `--tail --vol 112` 重量各種藏料的返還，再把 `hope` 調到總返還回到想要的位置。

這是純前端原型：石頭的真相在瀏覽器裡，正式上線時生成、估價與帳務必須移到伺服器端。

## 演出

編排在 [src/game/actions.js](src/game/actions.js)，工具模型在 [src/tools/rig.js](src/tools/rig.js)，粒子在 [src/fx/particles.js](src/fx/particles.js)。

工具也都是程式建的模型：車削件用帶倒角的輪廓旋轉成形（每段輪廓各自一個法線，所以稜線是利的），鑄件與鈑金用帶圓角的擠出，表面處理（滾花、錘紋漆、鑄鐵、螺紋）是由高度函式算出來的法線貼圖。

- **手電筒**：城垛式不鏽鋼攻擊頭（光從齒縫漏出）、鏡片與反光杯、車有散熱鰭片的頭部、銅環、O 環、滾花握把、帶指槽的尾蓋與橡膠按鍵、口袋夾。
- **牙機**（開窗用的吊機手柄，照實物尺寸：13 mm 磨頭、3 mm 柄、24 mm 機身）：鍍鎳金剛砂磨頭（圓柱弧頭，砂粒與鑽粒閃點、五道螺旋排水槽、槽裡積著乾掉的石漿、後端是沒鍍到的裸鋼環）、開四道縫的夾頭與六角螺帽、主軸上的鎖孔、沾著石漿點的不鏽鋼機鼻與軸承蓋、橘色 O 環、尖端磨亮的黑色滾花握把、雷射刻字、銅環、直紋快拆環、壓接套管、防折彈簧與螺旋紋軟軸；側面夾著一條滴水管，前端是對著磨頭的不鏽鋼針。轉起來時砂粒、排水槽、螺帽的稜角都糊成環狀殘影，針頭的水珠變成一道水線。
- **切石機**：以鋸片半徑為單位建模，依石頭大小縮放。鋸片是帶排屑槽的鋼芯加 30 片燒結金剛石刀頭；機頭有護罩（銘牌、警示標籤、擋水膠皮）、主軸座、鑄造搖臂、帶散熱鰭片的馬達與風罩、皮帶罩、進刀手把、兩條節式冷卻水管；機架有底座、兩根導柱與螺桿、頂部手輪、帶鋸縫與 T 槽的工作台、擋水邊，以及鋸片兩側各一的夾具。

- **開窗**：鏡頭推近，軟軸牙機的金剛砂磨頭先在落點吃進去，再沿螺旋由中心往外走，最後繞窗緣修一圈——**磨頭走到哪，石頭才開到哪**。窗口的網格在動工時就以完整深度算好，但整片先被托回原本的皮面（位置與法線都是）；磨頭每一幀把自己的軌跡蓋進一張 128² 的小貼圖（[src/stone/grind.js](src/stone/grind.js)：磨頭正下方磨到底，溝壁往外漸淺），頂點與片段著色器都讀這張圖決定每一點放下多少。所以窗口的形狀是磨頭實際掃出來的，軌跡邊緣由外到內依序露出皮殼、霧、肉。螺旋是照這個窗口實際的橢圓和邊緣起伏排的（每圈與上一圈重疊），磨頭貼在當下磨到的深度上。剛磨出來的肉面蓋著一層自己的石漿，噴水一擦才從霧面變成拋光。
- **碎屑**：磨頭和鋸片甩出來的碎片、石漿，取的是當下磨到那一層的顏色——皮殼的砂、皮下的暗殼、霧、肉（[src/stone/view.js](src/stone/view.js) 的 `crumb`）。碎片是不規則的石屑（薄片、長條、塊狀，每一粒形狀都不同，落地後躺平，底下有接觸陰影），石漿落地攤成邊緣化開的泥漬。它們只是當下的點綴：噴出來、落在石頭旁邊，一秒上下就縮掉消失，不會留在檯面上。
- **打燈**：手電筒壓在滑鼠指的位置，略微側傾讓出視線。擺放時用石頭自己的距離場檢查筒身上四圈取樣點，沿法線退到完全不穿進石頭為止，所以凹處、稜線、切面邊緣都貼得住。鋼圈翹起的那一側會漏出一小圈光；外洩光刻意壓得很低，因為打燈要看的是石頭裡面的光。
- **切刀**：石頭被搬上鋸台、轉到切面對齊鋸片，切石機從檯面後方推上來，左右夾具夾住；鋸片起轉（齒逐漸糊成殘影）、冷卻水打開、機頭沿立柱落下，鋸縫跟著鋸片的位置出現，石漿和水往前甩。切完機頭升起、夾具鬆開、機台退回；兩半推開時切面還蓋著石漿，心跳兩下，翻面、沖水，顏色才出來。
- **揭曉**：依漲跌幅分級——擦漲／切漲／大漲各有音效與金幣、閃光、衝擊波；切垮則是一沉。
- **金幣**（[src/fx/coins.js](src/fx/coins.js)）：方孔錢——圓形、中間方孔，外緣與方孔的內郭凸起，幣面「招財進寶」。每一枚都是一個剛體圓盤，不是粒子：
  - 噴出去時翻著筋斗飛，用邊緣著地會被那一點的衝量帶著轉、彈一兩下、晃著躺平。幣緣當成圓的，所以不會立在桌上。
  - 落在別的硬幣上就疊上去；只壓到一半就斜靠在對方的邊上。不穿桌面，不穿已經躺著的硬幣，碰到石頭會照石頭自己的距離場彈開、滑下來。
  - 做法：每枚硬幣在幣緣一圈、內圈和圓心共 21 個點上檢查底下是什麼（桌面、比它低的每一枚硬幣的頂面、石頭），再加兩個算出來的精確點——自己幣緣對著對方幣面的最低點、對方頂緣頂進自己的最高點。硬幣只會靠在比它低的硬幣上，所以不必整堆一起解。
  - 要靜止之前再把兩面整圈對鄰居檢查一次；還卡在別的硬幣裡就抬高、放平一點重新落，試幾次不行就往旁邊推下去。照遊戲實際的噴法測（三種獎級、各種石頭大小），靜止後幣與幣最深互入約 0.1 毫米，桌面以下 0.14 毫米，126 枚的物理一幀約 0.3–0.5 毫秒。
  - 底下的硬幣消失時，疊在上面的會醒過來往下掉；石頭被搬動時，躺在上面的也一樣。

| 揭曉 | 兩半相碰、推開（石頭在檯面上滑），心跳兩下，整桶水沖下去 |
| 漲跌 | 圍觀群眾的反應，照瑞麗、緬甸賭石現場一群人圍著看切石的樣子；底下墊的是中國大鼓（Dagu）和京劇鈸，每次只敲一下，不放旋律：**漲 150% 以上**大鑼＋驚呼轉歡呼＋鞭炮＋金幣；**漲 60–150%** 小鑼＋「喔～」＋金幣＋掌聲；**漲 15–60%**（切漲、擦漲）鈸配鼓框一擊「倉！」＋讚嘆；**持平**（含漲不到 15%）鼓框輕敲一下；**跌**群眾「唉」＋大鼓鼓心一聲悶「咚」；**垮**群眾倒抽一口氣＋低沉一擊＋大鼓重擊。切面出了裂另有一聲石裂 |
| 金幣 | 漲的時候噴出來的方孔錢自己帶聲音，跟著物理走：噴出的瞬間是一把硬幣撒出去的聲音（越多越響）；之後每一枚落地各響一下——落在絨布上是悶的一聲，落在別的硬幣上是清脆的「叮」，撞得越重越響，同時落下太多時自動稀疏；56 枚以上再墊一層真的倒硬幣的錄音，對在第一批落地的時間 |
| 賣出 | 買家的點鈔機刷刷刷數錢（金額越大數越久），數完「嗶」一聲、櫃台鈴；大賺再加一把金幣 |

### 怎麼做的

- **建置**：[tools/sfx_build.py](tools/sfx_build.py) 裡每個音效寫明來源（Freesound 編號或 Kenney 檔名）、裁切起訖秒數、疊哪幾層、高低通濾波、變速、淡入淡出；一次性音效統一響度後輸出 MP3，循環音效用等功率交叉淡化接成無縫後輸出 WAV（MP3 頭尾會補靜音，循環時會有空隙）。來源第一次執行時下載到專案的 `.sfx-cache/`（不進 git），之後重跑不必連網。改表格重跑即可：
  ```bash
  python -I tools/sfx_build.py            # 全部
  python -I tools/sfx_build.py saw_cut    # 只重做指定的
  ```
- **機器聲是分層即時驅動的**（[src/audio/sfx.js](src/audio/sfx.js) 的 `machine`）：啟動錄音播完前交棒給運轉循環；吃刀的循環隨負載淡入；兩者音高都隨負載往下沉。所以鋸子的聲音跟著畫面上鋸片吃進石頭的深淺走。
- **混音**：效果音與環境音分兩條匯流排，接壓縮器和硬限幅器。各音效的相對音量是實際錄下一整局遊戲的輸出後量出來調的：大漲最響，其次切漲、擦漲；環境音比效果音低約 20 dB；整局峰值 −1.2 dBFS、沒有削波。
- **怎麼挑的**：在 Freesound 只搜 CC0 授權，每個時機用多組關鍵字撈候選（約 1,400 筆），依標題、長度、下載數、評分選出 2–5 個，再畫音量包絡和頻譜圖挑段落、定裁切點。

## 測試

```bash
npm run dev                      # 先開著
node tools/smoke.mjs             # 買、擦、開窗、切兩刀、賣，每一步對帳；需要本機 Chrome（可用環境變數 CHROME 指定）
node tools/simulate.mjs --seed 51        # 一顆石頭的完整報告
node tools/simulate.mjs --seed 51 --lucky imperial --hidden 1   # 同一顆種子，強制長成藏色帝王綠（violet／spring／glass／vein／none）
node tools/simulate.mjs --n 800 --plays  # 返還表
node tools/simulate.mjs --n 2000 --tail  # 各種機緣的出現率、買不買得起、切一刀的倍數分佈
node tools/simulate.mjs --n 600 --fit    # 重新校正 tuning.js 的 calib（只用一般石頭、扣掉賭性溢價）
# 以上都可以加 --vol 112 改用遊戲實際的體積解析度（慢五倍）
```

網址參數（除錯用）：`?seed=51&fixed=1` 固定攤位（第一塊就是種子 51）且關閉自動降解析度；`&mine=hpakant&color=band&z=0.86` 指定第一塊的場口、出色方式、種水；`&body=grey&fog=yellow&black=1` 指定底色、霧、強制帶黑癬；`&lucky=imperial&hidden=1` 讓第一塊長成指定的機緣（`imperial`／`violet`／`spring`／`glass`／`vein`，`hidden=0` 是明料）；`&cash=90000000` 指定本金（只在 `gm: true` 時有效）；`&pick=0` 直接上手第一塊。`?rig=saw`（可加 `&spin=1&water=1`）、`?rig=grinder`（可加 `&spin=1`、`&zoom=1` 近看磨頭、`&far=1` 看整支含軟軸）或 `?rig=torch&on=1` 把工具模型單獨擺在檯面上打燈檢視。

## 效能

每塊石頭約 4 萬頂點、兩張 112³ 體積貼圖；生成一塊約半秒（在 Worker 裡）。玉肉每個像素最多約 70 次 3D 貼圖取樣。內顯（Intel）在 1280×720 無頭模式下各狀態都在 30 fps 上下；遊戲會依實際幀率自動調整解析度比例（0.55–1.5）。

## 已知限制

- 切面只能是平面，一塊最多再切到 8 塊。
- 一刀把凹形石頭切成三塊時，其中分開的兩塊仍算同一塊。
- 沒有議價；開價就是成交價。
- 觸控只支援單指旋轉與點擊，畫切線需要滑鼠。
